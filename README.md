# Standup Helper

Веб-приложение для управления списком участников, временем выступлений и командными заданиями. Приложение подготовлено для Cloudflare Workers и использует один Worker для статических файлов и серверного API.

## Архитектура

- `public/` — HTML, CSS и клиентский JavaScript.
- `src/worker.ts` — типизированная Hono-маршрутизация, авторизация и Worker API.
- `src/auth.ts` — Better Auth, регистрация по email/password и D1-сессии на 24 часа.
- `src/openrouter.ts` — генерация заданий через OpenRouter.
- `src/meetings.ts` и `src/speeches.ts` — стендап-сессии и серверный таймер выступлений.
- `src/assignments.ts` — серверная жеребьёвка и циклы заданий комнаты.
- `src/quizzes.ts` — шаблоны викторин, вопросы, варианты и права редакторов.
- `src/quiz-games.ts` — игровые запуски, snapshot вопросов и realtime-состояние лобби.
- `src/realtime.ts` — Durable Object и WebSocket-события для синхронизации комнаты.
- `src/errors.ts` — безопасная классификация ошибок.
- `src/env.ts` — типы Cloudflare bindings и переменных окружения.
- `migrations/` — версионируемая схема Cloudflare D1.
- `wrangler.jsonc` — конфигурация Cloudflare Worker `standup-helper`.

D1 подключена как binding `DB`. Миграции создают аккаунты и сессии Better Auth, профили приложения, постоянные комнаты, членство с ролями `owner`, `admin` и `member`, отдельные стендап-сессии, выступления, задания, шаблоны викторин и игровые запуски. Личный кабинет позволяет создавать комнаты и присоединяться по коду. Старый экран `/admin` пока остаётся локальным режимом для обратной совместимости; основная функциональность комнаты хранится на сервере.

Durable Object `RoomSync` подключён как binding `ROOM_SYNC`. Для каждой комнаты он поддерживает отдельный WebSocket-хаб, а D1 остаётся источником истины. Клиент перечитывает состояние после события и использует периодическое обновление только как резерв при разорванном соединении.

## Локальный запуск

Потребуются Node.js 22.6 или новее и API-ключ со страницы [OpenRouter Keys](https://openrouter.ai/settings/keys).

Установите зависимости:

```powershell
npm install
```

Создайте локальный файл с секретами:

```powershell
Copy-Item .dev.vars.example .dev.vars
```

Заполните `.dev.vars`:

```dotenv
BETTER_AUTH_SECRET=случайная-строка-не-короче-32-символов
OPENROUTER_API_KEY=ваш-ключ-openrouter
```

Случайный `BETTER_AUTH_SECRET` можно сгенерировать командой:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Не публикуйте содержимое `.dev.vars`. Файл исключён из Git.

Запустите локальную среду Cloudflare:

```powershell
npm run db:migrate:local
npm run dev
```

Wrangler покажет локальный адрес, обычно `http://localhost:8787`. Корневая страница содержит форму входа, личный кабинет доступен по `/dashboard`, а текущий экран таймера — по `/admin`.

Основные маршруты:

- `/dashboard` — личный кабинет и список комнат;
- `/rooms/:id` — информация о комнате и список её участников;
- `/api/rooms/:id/live` — авторизованный WebSocket комнаты;
- `/admin` — текущий локальный таймер встречи.

## Ручной production-деплой

Целевой адрес:

```text
https://standup-helper.mykhailo-zubkov.workers.dev
```

Сначала авторизуйте Wrangler:

```powershell
npx wrangler login
```

Добавьте production-секреты. Каждая команда попросит значение интерактивно — не вставляйте секрет непосредственно в текст команды:

```powershell
npx wrangler secret put BETTER_AUTH_SECRET
npx wrangler secret put OPENROUTER_API_KEY
```

После этого выполните:

```powershell
npm run db:migrate:remote
npm run deploy
```

Обычные настройки `OPENROUTER_MODEL` и `PUBLIC_APP_URL` находятся в `wrangler.jsonc`. Секретов в этом файле быть не должно.

## Авторизация

- любой пользователь может зарегистрироваться по имени, email и паролю;
- минимальная длина пароля — 12 символов;
- аккаунты и серверные сессии хранятся в D1;
- успешный вход создаёт `HttpOnly` cookie Better Auth;
- production-cookie передаётся только по HTTPS;
- срок сессии — 24 часа;
- выход удаляет cookie и отзывает запись сессии в D1;
- `/admin` и `/api/task` недоступны без действующей сессии;
- вход и регистрация ограничены по частоте запросов.

Подтверждение email и восстановление пароля пока не подключены, поскольку для них нужен транзакционный email-провайдер. До его подключения не используйте аккаунт как хранилище критически важных данных.

## Генерация заданий

Задания генерируются через бесплатный маршрутизатор `openrouter/free`, который выбирает доступную бесплатную модель с поддержкой нужного формата ответа. Маршрут можно изменить через `OPENROUTER_MODEL` в `wrangler.jsonc`.

Ключ OpenRouter доступен только Worker. Неавторизованный пользователь не может вызвать `/api/task`. Для временных ошибок выполняется до трёх попыток; ответы с ошибками содержат безопасный `requestId`.

## Комнаты

- комната является постоянным пространством команды, а не одноразовым звонком;
- создание комнаты автоматически назначает пользователя владельцем;
- каждая комната получает случайный шестизначный код;
- авторизованный пользователь может присоединиться по коду;
- пользователь видит только комнаты, в которых состоит;
- страница комнаты показывает имена и роли активных участников;
- владелец может назначать и снимать администраторов, исключать участников и архивировать комнату;
- администратор может менять название и лимит выступления, а также исключать обычных участников;
- участник и администратор могут самостоятельно выйти из комнаты;
- повторный вход ранее исключённого пользователя всегда возвращает его с обычной ролью `member`;
- чужая комната недоступна по прямому URL без членства.

## Стендап-сессии

- владелец или администратор запускает новую встречу внутри существующей комнаты;
- в одной комнате одновременно может идти только одна встреча;
- лимит выступления фиксируется в момент запуска, поэтому дальнейшее изменение настроек не меняет историю;
- любой участник комнаты видит текущий статус и последние завершённые встречи;
- владелец или администратор завершает активную встречу;
- после завершения можно запустить следующую встречу в той же комнате.

## Выступления

- владелец или администратор запускает таймер для любого активного участника комнаты;
- одновременно внутри стендапа может идти только одно выступление;
- таймер можно ставить на паузу, продолжать и завершать без потери накопленного времени;
- состояние таймера и история хранятся в D1 и восстанавливаются после обновления страницы;
- любой участник комнаты видит активного спикера, время и историю текущего стендапа;
- выступления дольше зафиксированного лимита отмечаются красным;
- активный стендап нельзя завершить, пока текущее выступление не закончено.

## Задания и жеребьёвка

- владелец или администратор генерирует задание прямо на странице комнаты;
- задания делятся на импровизационные для активного стендапа и подготовительные к следующему;
- текст генерируется OpenRouter на английском и русском, API-ключ остаётся только в Worker;
- для каждого типа задания ведётся полный круг активных участников;
- участник не выбирается повторно, пока задание не получат остальные, и не повторяется на границе двух кругов;
- любой участник видит последние назначения, а также отдельный список своих заданий;
- задания и завершённые выступления объединены в журнал действий комнаты.

## Викторины

- владелец и администраторы комнаты могут создавать, читать и редактировать шаблоны викторин;
- редактор поддерживает добавление, удаление и изменение порядка вопросов и вариантов ответа;
- викторина содержит от 1 до 50 вопросов, каждый с 2–4 вариантами и ровно одним правильным ответом;
- время ответа на вопрос настраивается в диапазоне от 5 до 120 секунд;
- все участники комнаты могут видеть безопасный список викторин без вопросов и правильных ответов;
- полный шаблон с правильными ответами доступен только владельцу и администраторам;
- удаление архивирует шаблон, чтобы будущая история игровых запусков оставалась целостной;
- изменения списка викторин публикуются в realtime-канал комнаты.

## Игровые сессии викторин

- владелец или администратор запускает из шаблона одно активное лобби на комнату;
- при создании игры вопросы и ответы копируются в неизменяемый snapshot;
- любой активный участник комнаты может войти в лобби или выйти до старта;
- запустить или отменить игру может только владелец или администратор;
- игра не запускается с пустым лобби;
- первый вопрос получает единый серверный timestamp в миллисекундах;
- участникам возвращаются варианты ответа без признака правильного варианта;
- каждое изменение лобби публикуется как `quiz-game.updated` через realtime-канал комнаты;
- схема D1 уже содержит участников, ответы, баллы и итоговые места для следующих этапов.

## Следующие этапы

После проверки production-размещения можно последовательно добавить:

1. Добавить экран realtime-лобби и игровую страницу поверх готового API.
2. Реализовать приём ответов, начисление баллов, переходы между вопросами и итоговую таблицу.
3. После проверки новой комнаты удалить устаревший локальный экран `/admin`.
